# Starcev Games Protocols

Единая производственная система для браузерных HTML5-игр Starcev Games.

**Protocol version:** `1.0.0`  
**Last reviewed:** `2026-09-11`  
**Baseline engine:** `Godot 4.7.2-stable` + GDScript + Web/Compatibility/WebGL 2.0  
**Primary platforms:** Яндекс Игры, Пикабу Игры

## Зачем нужен этот репозиторий

Этот репозиторий — источник истины для всех новых игр. Новая игра создаётся в отдельном пустом Git-репозитории. Агент получает две ссылки:

1. этот репозиторий с протоколами;
2. репозиторий конкретной игры.

Дальше он не изобретает производственный процесс заново, а работает по зафиксированным правилам: идея → прототип → проверка core loop → архитектура → UI/ассеты → платформы → реклама/сохранения → QA → релиз → аналитика → обновление протоколов.

## Главный принцип

> Всё повторяемое стандартизируем. Всё специфичное для игры оставляем в репозитории игры.

Протоколы должны уменьшать количество повторных объяснений, ошибок и расход токенов/времени. Если в конкретной игре обнаружена системная ошибка или более удачный подход, после проверки решение переносится обратно сюда.

## Базовые технические решения v1

- Godot `4.7.2-stable`, версия закрепляется внутри конкретного проекта и не меняется посреди разработки без причины.
- Только GDScript для web-проектов.
- Renderer: `Compatibility` / WebGL 2.0.
- Web export: **single-thread** по умолчанию.
- PWA и cross-origin isolation выключены для Яндекс/Пикабу, если конкретная задача не требует обратного.
- Игровая логика не вызывает SDK площадки напрямую.
- Local-first сохранения + облачная синхронизация.
- Русский интерфейс — обязательная базовая локализация; строки хранятся отдельно от логики.
- Управление и интерфейс проектируются одновременно для мыши и touch.
- Production-графика создаётся только под реальные слоты/размеры из `ASSET_MANIFEST`.
- Красивый концепт — это art direction, а не готовый UI.
- Rewarded — только осознанное действие игрока; fullscreen — только естественные паузы в gameplay.
- Никакая игра не уходит в релиз без web QA в реальном браузере.

## Definition of Done

Игра считается готовой только если одновременно:

- core loop завершён и понятен без внешней инструкции;
- есть достаточная длительность/реиграбельность;
- desktop и mobile управление реально проверены;
- resize/orientation не ломают UI;
- сохранения переживают перезапуск;
- облачная синхронизация работает там, где обязательна;
- реклама не ломает gameplay/audio/input;
- нет критических ошибок в браузерной консоли;
- первый экран загружается приемлемо быстро;
- графика в реальной игре соответствует утверждённому art direction;
- пройдены платформенные чек-листы;
- подготовлены обложки, иконки, скриншоты и описание;
- заполнен release report и назначен первый post-release review.

## Обновление протоколов

Протоколы — живой документ, но не место для хаотичных правок.

Любое изменение должно отвечать хотя бы одному условию:

- ошибка повторилась минимум в двух проектах;
- новое правило площадки делает старый подход неверным;
- найден способ заметно уменьшить время производства;
- найден способ заметно повысить качество, retention или доход;
- решение подтверждено реальным проектом/тестом.

История решений фиксируется в [`research/DECISIONS.md`](research/DECISIONS.md).
